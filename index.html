Morning Brief

LeadSourceReceivedSorted asMessage

Every problem the reviewer caught becomes a proposed rule for the agents. Nothing changes until the owner approves it.

The problem

An owner starts the day with leads to sort, calls to remember and follow-ups to write. Agents can do the first pass in minutes. Someone still has to check every output before it reaches a customer, because an email with the wrong price costs more than the time it saved.

How a morning runs

  1. Inputs arriveOvernight leads and yesterday's calls.
  2. Three agents workSort leads, summarize calls, draft follow-ups.
  3. The reviewer checksPrices, names, hours, promises, credentials.
  4. The owner decidesApprove, apply a fix, or hold. Nothing sends itself.

What is real and what is simulated

  • The agents are plain scripts so the demo runs offline on mock data. A real client build would put a model call where the templates are.
  • Four mistakes are planted on purpose, each one a failure real agents make: a stale cached price, an unfilled name field, a Sunday visit, and an unapproved promise.
  • The reviewer is independent code. It checks against the business's own price list and hours, never against the agent's cache. Its fixes are re-checked, and a run without the planted mistakes produces no draft findings.
  • One flag comes from the data and not from a planted agent fault: on Monday's call the rep quoted an old price. The reviewer sends that one to the owner as a decision, because the right answer is a business call.

How this would be measured for a real client

  • Drafts approved with no edits, as a share of all drafts.
  • Errors caught before send, and errors that got through.
  • Minutes from a new lead to the first reply.
  • Minutes the owner spends on review each morning.

Credential habits

  • No keys, passwords or tokens in the code, the data or this page.
  • .env is git-ignored and .env.example lists names with empty values.
  • The reviewer blocks any output that contains something shaped like a key or password.
  • A test scans every file in the repository for secret-shaped strings.
